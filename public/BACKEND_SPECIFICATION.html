1. Executive Summary & Core Platform Vision

This document serves as the comprehensive backend technical specification for developers building the full-scale production backend for the Tanzanian & East African Secondary School Digital Learning Ecosystem.

The system accommodates three core user personas: Students (Form 1 to 6), Teachers (Mwalimu), and School Administrators (Headmasters).

🤖 Baraka AI Study Companion

Gemini-powered tutor grounded in the NECTA secondary syllabus. Supports Swahili/English bilingual explanations and math step solvers.

🔴 Real-Time Live Sessions

Cross-browser classroom streaming with Server-Sent Events (SSE). Synchronizes presentation slides, live whiteboard, and pop quizzes.

🔑 Dual Authentication System

Supports instant Google OAuth 2.0 verification and school registration code authentication with Form-level classification.

📲 Parent SMS & Mobile Money

Automated SMS alerts for parents via African gateways (Beem Africa) and fee tracking via M-Pesa / Tigo Pesa integration.

3. Database Schema & Data Models

3.1 Users Table (`users` / `students`)

Field Name Data Type Description
id VARCHAR(64) [PK] Unique User Identifier / Hash
reg_no VARCHAR(32) School Reg No (e.g., BSS-2026-891)
name VARCHAR(128) Full Name
email VARCHAR(128) Email address
role ENUM 'student', 'teacher', 'admin'
class_level VARCHAR(32) Grade level (Form 1 through Form 6)
parent_phone VARCHAR(32) Parent mobile for SMS notifications
fees_paid BOOLEAN Tuition balance status flag

3.2 Live Session State (`live_sessions`)

Field Name Data Type Description
id VARCHAR(64) [PK] Session Identifier
is_active BOOLEAN Live stream active indicator
subject & topic VARCHAR(128) Subject and lesson topic name
whiteboard_text TEXT Live markdown canvas contents
presentation_slide_index INT Active slide position for students
active_quiz JSONB Question, options, correct index, and submission counts

4. API Endpoint Specifications

  • GET /api/auth/url — Generates Google OAuth 2.0 authorization redirect link.
  • POST /api/chat — Proxies queries to Google Gemini API (gemini-2.5-flash) with NECTA study prompts.
  • GET /api/live-session — Retrieves current live classroom state.
  • POST /api/live-session — Updates classroom state (teacher) and broadcasts to all clients.
  • GET /api/live-session/stream — Server-Sent Events (SSE) stream for instant cross-device updates.

5. Handover Checklist for Developers

  1. Set up Node.js v20+ project with TypeScript and Express or NestJS.
  2. Configure Google GenAI SDK with GEMINI_API_KEY environment variable.
  3. Deploy PostgreSQL database and run migrations based on Section 3 schemas.
  4. Configure SSE headers (Content-Type: text/event-stream) for low-latency session syncing.
  5. Implement Google OAuth 2.0 secrets in .env.
